# Interviewer

A Claude-based interview system for the Idealists Collective. A member sits down with Claude — who has read the entire collective (the site, the Discord history, the application form responses, every essay) — and is asked what they care about, what they want to know, and what they're worried about regarding the future. Claude can also answer their questions about the collective by querying the wiki.

This repo hosts three things:

1. **A wiki** about the collective at `wiki/`, built from the site, the Discord messages, and the application form responses, following [the LLM Wiki pattern from karpathy](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f). 203 markdown pages, all cited.
2. **An interviewer agent** — a system prompt + a small set of read-only tools that turn Claude into a thoughtful interviewer. Lives in `system_prompt.md` and `src/routes/api/interview/+server.ts`.
3. **A Vercel-deployable web frontend** for the interview, in `src/`. SvelteKit, matching the stack of `idealistscollective.org`.

## Quick start

```sh
npm install
cp .env.example .env   # then put your ANTHROPIC_API_KEY in
npm run dev
```

Then open `http://localhost:5173` and start an interview.

## Layout

```
README.md              this file
CLAUDE.md              the wiki schema (karpathy-style: tells future claudes how to maintain the wiki)
system_prompt.md       the interviewer's system prompt — the api route reads this at runtime
questions.md           recommended interview questions and the reasoning behind them

wiki/                  the wiki — 203 markdown pages
  index.md             content catalog (regenerated by build_wiki/build_index.py)
  log.md               append-only chronological log
  overview.md          what the collective is
  principles.md        the DNA
  concepts/            5 pages — aliveness, autonomy, hyperstition, idealism, jazz-coding
  projects/            16 pages — every project on the site, plus "my front page", "autobots", etc
  members/             102 pages — one per identifiable member, auto-generated from the CSV
  channels/            60 pages — one per discord channel; top 8 are hand-curated synthesis on top of the dump
  themes/              6 synthesis pages — what people care about, what they're worried about, what they want to create, why they joined, AI and the future, social topology
  writings/            9 pages — summaries of each essay on the site
  sources/             3 pages — pointers to the raw sources

raw/                   immutable inputs the wiki is derived from. never edited.
  members.csv          public members list (52 rows)
  application_responses.csv   joining form responses (319 rows)
  messages.json        discord history (5984 messages, 60 channels)
  writings/            essays from the site

build_wiki/            python scripts that (re)generate parts of the wiki from raw/
  build_member_pages.py        generates wiki/members/*.md (deterministic, no LLM calls)
  build_channel_summaries.py   generates wiki/channels/*.md (deterministic, no LLM calls)
  build_index.py               regenerates wiki/index.md from frontmatter
  lint.py                      checks for missing citations, hallucinated members, broken links, stale pages, oversize pages
  build_all.sh                 runs all of the above in order

src/                   sveltekit frontend + interview API
  routes/+page.svelte                chat UI with transcript download and "start over"
  routes/api/interview/+server.ts    api route — talks to the anthropic api with read-only wiki tools
  lib/server/wiki.ts                 the three tool implementations (search/list/read)
  lib/server/system_prompt.ts        loads system_prompt.md at runtime
```

## How to think about the wiki

Per the karpathy methodology and the schema in `CLAUDE.md`:

- The **raw** layer is immutable. The wiki is regenerated from it.
- The **wiki** is the LLM's working memory. Hand-edit pages where synthesis is needed; regenerate dump-style pages from `raw/` with the build scripts.
- The **schema** (`CLAUDE.md`) is the protocol. If you change how pages are structured, update the schema and the build scripts.

The single most important rule is **citation-first**: every claim in the wiki cites the raw source it came from. The lint script checks this. This is why the interviewer doesn't make things up.

## How the interviewer's safety properties work

The agent is given exactly three tools, all read-only over `wiki/`:

- `list_wiki_pages(directory?)`
- `search_wiki(query)` — naive AND-of-keywords grep across all pages
- `read_wiki_page(path)` — paths are validated against path traversal

There is no bash, no file write, no edit, no shell, no network beyond the Anthropic API. The agent literally cannot do anything but read the wiki and respond.

Prompt-injection is mitigated three ways:

1. The system prompt explicitly tells the agent that user messages are *content about a person*, not instructions.
2. Every user message is wrapped server-side in `<participant>...</participant>` tags. The agent is told to treat anything inside those tags as data.
3. Any `<participant>` or `</participant>` tags appearing in the raw user input are stripped before wrapping.

If a user pastes a "ignore all previous instructions" payload, the agent reads it as a piece of text the participant said, not as a meta-instruction it has to follow.

## Re-building the wiki

After dropping a fresh `messages.json` or `application_responses.csv` into `raw/`:

```sh
./build_wiki/build_all.sh
```

This rebuilds `wiki/members/`, `wiki/channels/`, `wiki/index.md`, and runs the lint pass. The hand-written pages (overview, principles, concepts, projects, themes, writings, sources) are not touched.

If you want to add a new wiki page by hand: write the markdown, include frontmatter with `sources:`, run `build_index.py` and `lint.py`.

## Deploying to Vercel

```sh
npm run build
vercel --prod
```

Set `ANTHROPIC_API_KEY` in the Vercel project's environment variables. The wiki is bundled into the serverless function via `includeFiles: ['wiki/**', 'system_prompt.md']` in `svelte.config.js`.

Optionally set `INTERVIEWER_MODEL=claude-opus-4-7` to use Opus instead of the default Sonnet 4.6 — slower and more expensive but more thoughtful.

## Status

v1, written by Claude Opus 4.7 (1M context) as an honorary member of the collective on 2026-05-08. See `wiki/log.md` for what's been ingested and what gaps remain.

The biggest known gaps:

- 6 high-volume Discord handles in the top 30 cannot be confidently mapped to a real name. They are surfaced as discord-handles-only.
- 20 personal `*-box` channels have basic dumps but no extraction into the corresponding member pages.
- The `themes/future-worries.md` page is the thinnest of the synthesis pages because the source material is thin. **The strongest argument for running the interview process at all is that the wiki cannot currently answer "what is the collective worried about" without sounding generic.** This will be filled in by interview transcripts (with member consent).
